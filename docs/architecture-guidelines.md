# 架构原则

目标是让维护者可以局部理解并安全修改系统，不为目录对称或未来假设增加机制。产品边界见[总体方案](design-proposal.md)，职责与资源所有权见[代码导航](technical-design.md)。

## 职责与依赖

| 责任 | 所有者 |
| --- | --- |
| 输入、输出、schema、错误契约和调用适配 | 工具 |
| 业务决定、授权、状态转换、副作用顺序及恢复策略 | 服务 |
| 严格读写、事务、索引和持久化健康状态 | 存储 |
| MCP/ACP、进程及操作系统协议 | 接入 |
| 依赖装配、运行实例及生命周期 | 应用入口 |
| 普通领域数据，不含业务行为或 SDK 对象 | 模型 |
| 展示与收集操作，通过服务执行 | Web 控制台、CLI |

服务只接收普通数据和窄能力，不依赖 SDK 上下文、HTTP 对象、UI 或完整进程对象。接入实现服务所需能力，由入口装配；存储不反向依赖服务或协议。禁止循环依赖、隐藏的全局可变状态和服务定位器。

CLI 覆盖 Web 的全部配置和管理操作，两端必须复用同一套底层服务，不维护各自的业务规则。

按业务能力聚合模型、规则和服务，存储实现与协议接入保留明确边界。新增职责必须指定状态修改入口和资源所有者；保持关键行为测试，不加空目录、无人使用的接口、转发层或动态插件平台。实际分层和随 `npm run check` 执行的依赖检查见[代码导航](technical-design.md#依赖与一致性边界)。

## 执行与持久性

- 复用 SDK 模型循环；只有协调员推进既定 DAG，不再增加规划器或并行节点调度器。
- Task、Run、模型会话、ACP Session 和外部业务记录各有责任主体，不能互相代替。
- 先可靠保存接收或派发意图，再触发外部工作。业务幂等不能证明外部副作用只发生一次。
- 只有明确接受的执行端交付才能解锁依赖；模型判断不能替代领域证据。
- 未收到结果不等于没有执行。中断或结果不明时阻止新派发，包括模型新发起的调用；不自动重试、切换 Agent 或创建新身份重放。
- 截止时间限制新执行开始，执行超时是另一规则。客户端断开不取消任务；取消不回滚外部操作。
- 资源有明确所有者，关闭幂等，关闭后拒绝操作。先停止新派发，再处理活动执行、网络与存储，最后释放所有权。
- 目录锁、事务和 worker 监督解决不同问题，不等于跨机一致性、无孤儿进程或工具沙箱。

## 权限与敏感数据

- 执行端声明能力、管理员授权、真实验证证据分别表达，不能相互推导。
- 只有管理员注册的执行端可启动。命令、凭据和能力端点属于管理员；任务可选择现有绝对工作空间，但路径校验不是授权或沙箱。
- 授权须在可控制的实际操作入口检查。沿用执行端原生授权，额外 ACP 审批请求一律拒绝；`unattendedApproved` 不能证明所有原生工具已受控。
- Prompt、角色、技能、工具标题、协议成功和人工事实回复都不授予权限。取消、恢复和跨 Agent 传递不能扩大授权。
- 无人值守执行不等待交互审批；授权不充分或元数据不足时拒绝，不退回更宽权限或自动永久允许。
- MCP token、管理员 token、协调模型与执行端凭据分开；执行端继承用户原生环境前过滤服务私密变量，不有意记录秘密。Agent 输出和协调日志仍可能敏感。
- 优先使用执行端原生配置，不读取其私有业务存储格式，不将特定领域规则塞进平台。

## 存储与发布

使用本项目版本，不复制其他项目的存储标记。调研阶段不保留兼容层、额外版本计数或旧执行引擎；单节点和多节点共用 Task API。

新库初始化与既有数据升级分开。严格加载支持的契约，损坏或未知数据拒绝使用。普通启动不静默迁移、猜测修复或删除历史。

实际转换应是独立离线操作：声明源与目标格式、停止服务并取得排他所有权、备份、转换后验证、支持显式接续。不通过重放外部请求或重建工作空间修复记录，不引入文件哈希验证。
