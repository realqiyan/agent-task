# Task 持续对话与任务记忆

当前未发布源码已接入 Task 级会话、可靠输入、Document 记忆和补充交付。本文保留设计理由与安全约束；字段和流程见[代码导航](technical-design.md)，验证范围见[验证说明](validation.md#task-持续对话与记忆)。本地测试不代表真实模型会正确选择事实、维护记忆或判断补充工作的影响。

实现基于 pi durable 1.3.0，实际依赖以 [package.json](../package.json) 为准。不保留旧工具别名或旧持久化格式，不自动转换或删除历史数据。

## 一条 Task 会话，多个独立 Run

用户只与任务协调员对话，节点不是独立聊天入口。MCP 调用方仍定义固定 DAG、节点要求、依赖和执行端指派；协调员推进、澄清和验收，不拆解任务、增加可选节点或重写计划。

一个 Task 始终绑定同一协调员逻辑会话。Run 是有明确意图和预算的一次业务执行，不等于 SDK 从输入到回答的内部 run，也不等于 SDK 的 generation/tool task。完成、取消或未来触发耗尽都不关闭 Task 对话；终结 Run 不重新打开。

同一 Task 至多一个协调所有者和一个活动业务 Run。复用 SDK 的模型循环、inbox 和压缩，不另建节点调度器。空闲 Harness 可以关闭；重新打开必须验证原绑定。已绑定的会话文件、身份或任务记忆缺失时拒绝继续，不能创建空会话冒充恢复。

执行准入与对话分离：

- 普通消息不启动空闲 ACP 工作，也不回答待决问题。等待期间可以讨论，但只有明确的问题回答才能解除业务等待。
- 额外执行需要显式补充意图。活动 Run 内追加工作不重置预算；终结后以同一 Task 的成功 Run 为基线创建补充 Run，不把失败、取消或中断 Run 当作重试入口。
- 暂停或取消未来触发不禁止对话，也不授予新执行权限。显式补充仍检查截止时间、执行端、资源和不确定结果。
- 每次协调唤醒都有步数和时长限制。消息不延长活动 Run、待决问题或原 ACP 会话的期限。

## 输入可靠性与公开记录

[TaskConversations](../src/tasks/conversations.ts)先在业务 SQLite 接收输入，再由协调接入使用稳定消息身份提交 SDK inbox。普通消息与明确回答共享 Task 级请求键：相同规范化请求返回原回执，不同内容或输入种类冲突。[TaskRuns](../src/tasks/runs.ts)将回答与 Run 续接、补充意图与新 Run 分别原子提交。

业务库与 durable 库不是一个事务。提交后回执未落库的恢复必须找回同一 requestId，不创建新输入或重放 ACP。终结 Run 的回执与公开输出可以只读对账，不能为补齐展示而重新运行模型或工具。

回执区分已保存、已提交、已处理和未能处理；它们不证明事实已被采纳或外部工作已成功。公开记录包含用户消息、协调员已提交的公开文本、问题、总结和失败说明，不包含思维、内部 system prompt 或 SDK 工具日志。分页读取不推进执行。

收到消息不打断活动 ACP turn，也不阻止已有输出落库。新派发、验收、提问和完成前必须处理尚未判定相关性的本轮输入。模型调用始终绑定原准入身份和具体 Run，不能悄悄改绑到最新 Run。取消保留已接收消息，并明确报告未执行输入的原因。

## 固定要求与补充交付

服务始终提供整体目标、节点原始要求和有效上游引用；协调员选择相关用户事实并说明本次工作。首轮与后续轮次使用相同的上下文构建规则，不广播全部对话或复制所有节点聊天。实际采用的事实、上下游交付和会话身份保留在执行记录中；有界读取可以回查完整依据。历史读取不改变执行绑定；节点可选上下文限于本轮或 Task 级、已观察且未失败的用户消息。

旧交付及验收理由不可变。补充产生新交付；未改变的成果可显式复用，但须保留来源，不能伪报为本轮重新执行。新事实和上游修订要求重新审查受影响结果；未处理的结果不能解锁依赖或支持最终完成。正在执行的下游可以保存输出，但旧输入对应的结果不能直接验收。

例如 A 分析、B 成文、C 发布：更新 A 不等于重新运行 B、C。协调员判断全局影响，ACP 处理局部工作；已发布或发送等外部操作不能因为上游修正而自动重复。是否正确判断影响仍需要真实模型验收。

已验收的 ACP 会话可有界保留或释放，不并发 prompt、不延长原寿命。原工作明确完成后，获准的新补充可用固定执行端的新会话和旧交付上下文；这不是会话恢复或原操作重试。未验收、已中断或结果不明时禁止以新会话补齐。Task 会话长期保留不承诺 ACP 会话永久存在。

## 三层记忆，业务账本为准

- **业务账本**保存输入、准入、执行、等待和不可变交付，是状态与权限的权威来源。
- **durable 历史与压缩**保存协调上下文，继续使用 SDK 能力。
- **任务 Document**保存有界的事实、决定、注意事项、错误教训和未决问题，不复制完整状态机。

[任务 Document](../src/integrations/coordinator/memory.ts)使用 conversation scope；SDK 的 task scope 随内部任务终结，不适合产品 Task 的长期记忆。笔记保留带类型的来源与适用范围，并区分来源陈述和协调员推断，不将模型标注当作用户确认。[引用校验](../src/tasks/conversations.ts)只核验记录存在及归属，不能保证笔记的语义或适用范围正确。单次运行的日期、数量和外部状态不能自动成为未来运行的常量。模型可以通过受控工具读写笔记，外部 MCP 不提供通用 Document 写入口。

笔记与账本分别提交，先有业务事实再形成笔记。文档读取失败不能伪装成空记忆继续；fail-open hook 之外，实际 provider 与工具入口仍须拒绝失败上下文。记忆、摘要、用户消息和模型判断都不授予权限，也不能清除不确定结果。

## 使用与实现入口

普通对话使用 `task_message_send`，公开记录使用 `task_message_list`；回答待决问题使用 `task_question_answer`。显式补充通过消息的执行意图与 Run 引用表达。Task、Run、question 和 message 使用明确身份；完整契约与限制见 [task-contract.ts](../src/protocol/task-contract.ts)、[mcp-contract.ts](../src/protocol/mcp-contract.ts)。

未来触发由 `task_schedule_control` 管理，CLI 对应 `task schedule pause/resume/cancel`。Web 和 CLI 保持管理员配置、只读任务与未来触发控制的边界，不新增对话写入口；认证仍与 MCP 分离。

职责入口：

- [TaskConversations](../src/tasks/conversations.ts)：输入、回执、绑定和公开消息。
- [TaskRuns](../src/tasks/runs.ts)：Run 唯一业务写入口、派发、补充和交付审查。
- [TaskSupervisor](../src/tasks/supervisor.ts)、[NodeSessions](../src/tasks/sessions.ts)：单所有者监督与有界资源。
- [协调接入](../src/integrations/coordinator/coordinator.ts)、[会话存储](../src/integrations/coordinator/storage.ts)：SDK inbox、Document、模型循环与公开投影。

不包括 ACP 执行中即时插话、自动 session/load/resume、未知结果的强制恢复、跨 Task 记忆、通用插件平台、远程执行或任意计划编辑。尚未验证的能力不能从 SDK 接口或本地测试通过中推导。
